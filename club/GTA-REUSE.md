# 后续主线复用清单

本轮交付独立 Club。原有主线行为、入口和存档不在重写范围内，不能用 Club 的通过结果替代主线验收。

7.1 的追尾／引擎盖／驾驶舱相机、实时仪表，以及 GT 跑车和 AKM 的原生关节可沿用同一接入边界。复用外部模型时必须一起保留 [素材来源、授权与修改说明](ASSETS.md) 和游戏内作者鸣谢。

| 顺序 | 可复用的基础 | 主线接入工作 | 下一步的验收出口 |
| --- | --- | --- | --- |
| 1. 步行 | 120 Hz 时钟、输入归属、视角、暂停、触屏捕获、场景资源生命周期 | 把主线步行规则和查询抽离；加入与主线地图一致的碰撞查询、楼梯与边缘处理 | 同一段路线上键鼠和触屏可走、停、转向；暂停后无漂移；不穿墙、不改变原任务状态 |
| 2. 进入并驾驶 | 赛车模拟边界、驾驶舱相机、原生车轮／方向盘／仪表关节、车辆高低 LOD | 接入车辆选择和进入条件；状态机独占步行／驾驶控制；映射主线交通与碰撞规则 | 走近车辆 → 上车 → 驾驶 → 停车；输入与相机归属唯一；无双物理状态 |
| 3. 下车并射击 | 武器 GLB、弹匣／枪机动作、开火／换弹输入与声音、第一人称视角 | 保留主线枪械平衡、伤害、遮挡和命中规则；将纯射线／几何查询与视觉特效分开 | 下车后恢复步行位置和镜头，开火、瞄准、换弹可连续完成；渲染画质不影响伤害 |
| 4. NPC 与任务 | 事件输出接口、确定性种子、有限历史、独立渲染快照 | 主线 NPC 状态、导航、交通与任务触发单独迁移；Club 不包含这些系统 | 原有任务起点、追踪、失败、重试、完成顺序均可复现；NPC 不由渲染帧数驱动 |
| 5. 存档 | 验证式导入、复制迁移、失败可见、本地备份 | 为主线建立独立新版本和迁移器；先读取旧档，不覆盖原档；迁移车辆／NPC／任务关联 ID | 新旧档往返测试、损坏恢复、任务中重载、车辆内重载、跨版本兼容均通过 |

接入顺序按上表推进；每一步先形成可运行的主线垂直流程，再扩大迁移范围。保留当前主线入口供回归对照，直到替代流程有完整证据。

模型边界统一为 glTF 2.0／GLB、米、Y 向上、右手坐标系、局部 -Z 向前。稳定资源 ID 和 `joint:*` 节点可复用；新生成的衍生文件进入独立目录，原始 Blender 手工修改继续作为资源来源。碰撞范围是资源元数据，游戏规则仍需使用经过验证的权威碰撞实现。

Club 没有初始化 Havok 或 Ammo。主线若确实需要刚体后端，应先定义步进、创建／删除物体、位姿快照和查询接口，再替换原有实现；不得同时让两个后端写同一物体的位置。Babylon 与 PlayCanvas 的渲染适配不应各自维护一套主线规则。

验收数据要同时保留行为测试、原生操作录像／截图、正常帧循环的帧时间分位数、首交互时间与实际持续运行的资源趋势。当前测试设备上的 Club 性能不代表大地图、NPC 或实体手机的性能。
