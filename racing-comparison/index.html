同一份模型与纹理、同一随机种子、120 Hz 固定步长。三种渲染管线的材质和后处理实现有差别，并非像素级一致。跑分须分别打开、保持前台、使用相同窗口与画质；统计排除前 3 秒。已有保存记录来自本机 Codex 内置浏览器；加载计时包含引擎脚本读取、解析、资源与初始渲染；来自本地 HTTP，未清除浏览器缓存，不代表公网冷启动。接近 60 FPS 时可能受显示刷新率限制。引擎体积是本地发行脚本的未压缩字节数，不含共用资源；不能直接当成网络传输量。尚未编译的一版不会填入推测数值。

怎么选：结合这份原型

维度Babylon.jsPlayCanvasUnity WebGL
当前驾驶手感共用同一份 120 Hz 模拟、输入和音效；手感差异主要来自帧耗时与渲染表现。C# 移植已写入，30 个一致性检查点尚未执行。
画面处理现有配置色调较深，座舱与路面反射层次明显。现有配置更明亮，物体轮廓清晰；曝光与环境滤波仍可调整。需要实际构建后观察。
开发工作方式当前是代码主导，调试和接入网页方便。当前用独立引擎；后续可评估在线 Editor 的场景编辑与协作。需要安装编辑器与 Web 模块，编译后再到浏览器验证。
适用方向继续完善目前由代码生成场景的网页游戏。继续做轻量网页版本；需要可视化场景工作流时再接 Editor。已有 Unity 资产、团队经验或多平台计划时再评估。

上面是本项目的实现观察与建议，不是引擎能力排名。PlayCanvas Editor 尚未接入，本次未创建云端项目。公开文档：独立引擎 · PlayCanvas Editor。玩法深度、车辆与环境美术质量仍需继续设计，换引擎本身不会补齐这些内容。

Unity 版：完成编译所需步骤

本机检查时可用磁盘约 5.6 GB，未发现 Unity 编辑器或许可证。工程与 WebGL 构建脚本已提供；编译和画面验证仍待完成。

  1. 准备足够安装与构建空间；安装 Unity Hub，登录并激活你可用的许可证。
  2. 安装 Unity 6.0（工程目标 6000.0.73f1），勾选 Web Build Support。
  3. 在此对比目录运行下方命令；也可通过 Hub 打开 unity 文件夹，选择 Coast Rush → Build WebGL。
zsh tools/build_unity.sh

构建成功后会生成真正的 Unity loader、data 与 WebAssembly 文件，对比页会自动启用 Unity 试玩入口。Unity 许可证官方说明 ↗
